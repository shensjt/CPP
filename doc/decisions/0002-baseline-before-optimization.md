# ADR-0002：先基线，再优化

- 状态：Accepted
- 日期：2026-11-19
- 关联：[benchmarks/plan.md](../benchmarks/plan.md)
- 取代：无

## 背景

v1.0 计划里既有性能数据，也有架构升级。没有基线就升级，无法判断：

- 当前瓶颈在哪里；
- 优化是否有效；
- 是否值得增加复杂度。

## 决策

先做 v1.0-A 基线，再决定 B 阶段做什么：

```text
A 基线（当前架构）
  → B 优化 A/B
  → C 生产接入 + 生产基线
  → D 生产复测 + 封版
```

规则：

- 实验室数据直连 `127.0.0.1`，生产数据走 HTTPS，分开记录；
- 每组 3 次，取中位数；
- 固定 commit、工具、命令、环境；
- 数据不达标时保留当前实现，写决策记录，不为优化而优化。

## 备选

- 直接做主从 Reactor：否决，没有数据支持；
- 只做 sendfile：否决，先看整体瓶颈；
- 不做数据：否决，面试和后续优化都没有依据。

## 后果

- v1.0-B 的候选必须由 A 的数据触发；
- 如果 A 显示没有明显瓶颈，B 可以缩水成决策记录；
- v0.5.0 作为稳定回退 tag。
