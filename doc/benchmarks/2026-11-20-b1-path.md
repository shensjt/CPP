# 2026-11-20 B1：路径缓存 + 单次 stat

> 状态：已评估，**不合并**。
> 分支：`feat/v1.0-b1-path`
> server 代码：B1 分支
> 决策：[ADR-0004](../decisions/0004-b1-path-cache-not-merged.md)

## 改动

- `StaticFileHandler` 增加 URL -> 规范化路径的 1MB LRU；
- miss 才做 `weakly_canonical`；
- `is_directory` / `is_regular_file` / `stat` 合并为一次 `lstat`；
- 目录才补 `index.html` 再 `lstat`；
- `lstat` 发现路径被替换为符号链接时，重新规范化并做 root 检查；
- 新增 SF21（删除/重建）、SF22（缓存后符号链接替换）测试。

## A/B 数据

同一份 `build/bench-www`，baseline 和 B1 交替运行，各 3 次 × 30s，100 连接。

### t4

| 版本 | QPS | P50 | P99 | worker 平均 CPU | io CPU |
|---|---:|---:|---:|---:|---:|
| baseline | 18,761 | 4.66ms | 16.05ms | 77.8% | 23.1% |
| B1 | 18,366 | 4.65ms | 17.97ms | 68.2% | 24.1% |

### t8

| 版本 | QPS | P50 | P99 | worker 平均 CPU | io CPU |
|---|---:|---:|---:|---:|---:|
| baseline | 19,055 | 4.37ms | 19.41ms | 50.8% | 28.8% |
| B1 | 19,919 | 4.22ms | 16.31ms | 45.2% | 30.1% |

## 系统调用

B1 下 strace：

```text
readlink      0        （baseline 约 5/请求）
newfstatat    2/请求   （baseline 约 4/请求）
epoll_ctl     1/请求
```

`strace` 会显著降低 QPS，只看次数。

## 结论

B1 确实减少了路径解析：

- readlink 归零；
- stat 减半；
- worker CPU 下降约 10%。

但 QPS / P99 在不同轮次之间波动很大：

- t4 一次 B1 略好，一次略差；
- t8 一次 +4.5% QPS、P99 改善，另一次差异不大。

没有稳定的 QPS +20% 或 P99 -30% 收益，说明当前瓶颈更多在客户端/内核/共享路径，而不是路径解析本身。

因此：

```text
B1 不合并到 fast-track
保留分支和代码作为实验记录
继续 B2：body 拷贝
```
