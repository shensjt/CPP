## 一句话

把博客从自研 `build.py` 切换到 MkDocs Material：内容用文件夹组织，构建和发布各一条命令，发布不重启容器。

## 本版本范围

### 内容站

- 使用 MkDocs Material，配置在 `blog/mkdocs.yml`；
- 真实内容放 `blog/content/`，演示内容放 `blog/demo/`；
- 一个顶层目录一个分块，`index.md` 是分块首页；
- 文件夹结构自动生成顶部 tabs 和侧边导航；
- 站内链接写相对 `.md`，构建时改写成 HTML URL；
- `mkdocs build --strict` 校验断链和锚点；
- 搜索、代码高亮、深色模式、上一篇/下一篇由 Material 提供；
- 生成 `sitemap.xml` 和 `search/search_index.json`；
- 真实内容不进入公开仓库，`blog/content/` 已 gitignore。

### 发布

- `make publish` 调用 `scripts/publish-content.sh`；
- 流程：构建 → 空构建保护 → `www.prev` 快照 → rsync → smoke → 失败回滚；
- rsync 使用 `--delete-after --delay-updates --chmod=D755,F644`；
- smoke 检查 `/` 和 `/sitemap.xml`；
- 支持 `SSH_KEY` 指定非默认 SSH key；
- 内容发布不重启容器；v0.4 的 LRU 按 mtime/size 失效。

### 服务器

- 内容目录迁移到 `/opt/sjtweb-runtime/www`；
- 生产 compose 使用 bind mount：
  - `/opt/sjtweb-runtime/www:/app/www:ro`；
- 容器内 demo 被宿主机目录遮住，不会覆盖真实内容；
- 首次发布前保留旧内容和 compose 备份。

### Docker / CI / CD

- Docker builder 使用 Python venv + `mkdocs-material`；
- 支持 `PIP_INDEX_URL`，国内构建可用 Aliyun PyPI 镜像；
- CI verify 使用 `setup-python` + `pip install -r blog/requirements.txt`；
- CI docker smoke 和 CD smoke 从 `/css/style.css` 改为 `/sitemap.xml`；
- 真实内容不进 CI，也不会打进镜像。

### 清理与文档

- 删除 `blog/scripts/build.py`、`blog/templates/`、`blog/config.yaml`；
- 删除旧 `deploy/` systemd 部署目录；
- 新增 `doc/blog-pipeline.md`；
- 新增 `doc/runbooks/publish-content.md`；
- 更新 `README.md`、`doc/architecture.md`、部署与回滚 runbook。

## 已知限制

- 内容发布是本地脚本，没有 push-to-publish；
- 只有一份 `www.prev` 快照，连续两次坏发布会覆盖好版本；
- `--strict` 主要校验链接和锚点，图片缺失不一定失败；
- 自定义 404 未接入服务器；
- 服务器 MIME 覆盖 png / jpg / gif / svg / ico，webp / avif 需要先补 MIME；
- 中文搜索效果取决于 Material 的分词；
- 旧 URL `/posts/...` 和 `/devlog.html` 已失效；
- 生产 compose 目前仍只在服务器上，未纳入仓库。
