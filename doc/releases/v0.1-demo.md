## 一句话

第一个可 clone、可构建、可一键部署的 C++ Web 服务器 + 静态博客示例。

## 本版本范围

包含：

- epoll + 线程池的静态 Web 服务器；
- HTTP/1.1 解析、keep-alive、静态文件、LRU 缓存；
- 双缓冲异步日志、空闲连接超时；
- Markdown → HTML 的博客构建脚本；
- systemd unit、Caddy 反代、部署与生命周期脚本；
- 5 个测试可执行文件。

## 功能

- 线程池 + 阻塞队列，任务投递与优雅停机；
- epoll 事件循环，非阻塞 IO，`EPOLLONESHOT` 下 worker 拥有连接；
- 分段 Buffer，`readv` 读取，处理半包/粘包；
- HTTP/1.1 请求解析：请求行、Headers、Body 状态机；
- 静态文件服务：MIME、目录 index、HEAD、404/403/405/400；
- keep-alive 与流水线，`CloseAfterWrite` 保证响应发完再关；
- LRU 文件缓存（默认 16MB）；
- 双缓冲异步日志，everysec fsync，按大小滚动；
- 空闲连接超时，默认 60 秒；
- 路径穿越、URL 编码绕过、符号链接逃逸防护。

## 架构

```text
浏览器
  │ HTTPS
  ▼
Caddy（TLS / 反向代理）
  │ HTTP/1.1 127.0.0.1:8080
  ▼
TcpServer
  ├── Epoll             事件通知
  ├── ThreadPool        worker
  └── TcpConnection     fd + 读/写 Buffer
        ├── HttpParser
        ├── StaticFileHandler ── LruCache
        └── HttpResponse
```

- IO 线程只做 `epoll_wait` 和分发；
- worker 负责连接的读写、HTTP 解析和静态文件处理；
- 连接注册 `EPOLLONESHOT`，同一 fd 同一时刻只有一个 worker；
- TLS 由 Caddy 处理，C++ 只跑明文 HTTP。

## 性能

环境：WSL2 / Ubuntu，AMD Ryzen 7 7840H，16 逻辑核；客户端与服务端同机，数字只用于相对比较。

Echo（64B payload，8 客户端）：

- 单 IO 线程：约 37k QPS
- 4 worker：约 34k QPS

Echo（32 客户端）：

- 单 IO 线程：约 61k QPS
- 4 worker：约 74k QPS

HTTP keep-alive（`GET /`，1.35KB 响应，16 客户端）：

- 单 IO 线程：约 9.5k QPS
- 4 worker：约 23.5k QPS

结论：Echo 这类几乎无计算量的场景，线程池开销大于收益；HTTP 解析 + 静态文件有实际工作，4 worker 提升约 2.5 倍。

## 已知限制

- 没有实现 sendfile，大文件仍走用户态缓冲；
- 内存池尚未接入 Web 服务器，目前作为独立组件；
- TLS 不在 C++ 内实现，交给 Caddy；
- 没有限流、连接数上限和认证；
- 博客仓库只带一篇演示文章，真实内容在本地维护、不入库。

## 部署

```bash
sudo bash deploy/setup.sh     # 安装/更新 unit 并启动
sudo bash deploy/stop.sh      # 停止服务
sudo bash deploy/restart.sh   # 重启并做本地健康检查
sudo bash deploy/status.sh    # 状态、端口、请求、最近日志
```

- 进程由 systemd 管理；
- Caddy 负责 TLS 和反代；
- 没有自动回滚；回滚方式是手动切回上一版二进制和 `www/`。

## 后记（2026-11-18 补记）

`TcpServer` 在 `EPOLLONESHOT` 的重新注册与 `InFlight` 清除之间存在竞争窗口，TSan 在加入 CI 后发现两处数据竞争。详见 [incidents/2026-11-18-tsan-connection-race.md](../incidents/2026-11-18-tsan-connection-race.md)。

同一轮 CI 还暴露了 fd 复用导致的 `HttpParser` UAF，详见 [incidents/2026-11-18-fd-reuse-parser-uaf.md](../incidents/2026-11-18-fd-reuse-parser-uaf.md)。两处缺陷都存在于 `v0.1-demo`。
