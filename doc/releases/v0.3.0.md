## 一句话

完成从开发到上线的工程化闭环：CI、容器化、CD 和部署回滚。

## 本版本范围

### CI

- `verify`：Release 构建 + 6 个测试可执行文件 + 博客构建
- `asan`：ASan/UBSan
- `tsan`：TSan
- `docker`：构建镜像并启动容器做冒烟测试

### 构建

- HTML 构建产物统一到 `build/www`
- 本地 `make blog` / `make run` 使用 `build/www`
- `make verify` 保持独立的 `build/verify-www`

### 容器

- 多阶段 Dockerfile：builder 编译 `web_server`、生成 demo `www`
- runtime 只包含 `web_server` 和 `www`，镜像约 118MB
- 非 root 用户 `app`（UID 10001）
- 容器内监听 `0.0.0.0:8080`
- `compose.yaml` 用于本地验证
- `.dockerignore` 排除 `docs/`、`build/`、`tests/` 等

### CD

- 触发：push 到 `main`
- 构建并推送 `sha-<commit>` 镜像到阿里云 ACR
- SSH 到 ECS，更新 `/opt/sjtweb-runtime/.env`
- `docker compose pull` / `up -d`
- smoke test：`/` 和 `/css/style.css`
- 失败恢复 `.env.prev` 并重新 `up -d`

### 服务器

- 容器运行在 `0.0.0.0:8080`
- 内容只读挂载：`/opt/sjtwebserver/projects/web_server/www:/app/www:ro`
- systemd `sjtwebserver` 已 stop / disable，unit 保留作回滚兜底
- 当前没有域名和 TLS，入口为 `http://39.106.115.254:8080`

### 文档

- `v0.1-demo`、`v0.2-kv` 发布记录
- 两个网络层 incident：
  - TcpServer 连接所有权交接竞态
  - fd 复用导致的 HttpParser UAF
- 部署与回滚 runbook

## 验证

- CI 四个 job 全绿
- 手动链路验证：
  - 本地构建镜像
  - 推送到 ACR
  - `deploy` 用户 SSH 登录
  - 服务器拉取镜像
  - 容器在 8080 返回 200
- 首次 CD 成功：`main` 合并后自动部署 `sha-243ef98`，站点返回 200

## 已知限制

- 没有域名和 TLS，直接通过 IP:8080 提供 HTTP
- GitHub runner 到 ACR 认证端点偶发 `connection reset`；重跑 deploy job 即可
- LRU 缓存没有失效机制，内容更新后需要重启容器
- 没有 health / version 端点；CD 冒烟测试只覆盖 `/` 和 CSS
- 内容流水线（内容版本、校验、独立发布）尚未实现
- systemd unit 仍保留，回滚时需与容器互斥使用 8080
